# Changelog

Everything that has changed in [CreaBus Tool](https://github.com/CreavisionTechnology/creabus-tool),
newest first. Dates are the day a version was tagged; a version marked
*unreleased* has no download yet.

Downloads live on the
[releases page](https://github.com/CreavisionTechnology/creabus-tool/releases).
Versions follow [semantic versioning](https://semver.org): while the leading
number is 0, anything may still change.

## 0.0.3 — unreleased

Renamed to **CreaBus Tool**, relicensed to the **GPL**, and the expression
language turned into a real boundary. Also the first version shaped by using
the tool against real hardware rather than against itself.

### Changed — name and licence

- **Renamed from Modbus Tool to CreaBus Tool.** *Modbus* is Schneider
  Electric's registered trademark; using it descriptively ("speaks Modbus TCP
  and RTU") is fine, using it as the name of a product that is sold is not
  worth the exposure. The Python package is `creabus_tool`, the binaries are
  `creabus-tool` and `creabus-tool-cli`.
- **Relicensed from MIT to the GNU General Public License v3 or later.** You
  may still run it for anything, privately or commercially, with no fee and
  nothing to report. What changed is that anyone who *distributes* it, or
  something built from it, must do so under the GPL with source. Nothing was
  taken from anybody: the repository was private and had never been published
  under MIT.
- **Contributions now need a [contributor licence agreement](CLA.md).** You
  keep your copyright, nothing is assigned, and your work stays in the free
  version — and Creavision may also use it in CreaBus Tool Pro. Stated up
  front rather than in the small print, and accepted by signing off a commit.

### Fixed — security

- **A device profile could run arbitrary code.** Expressions were evaluated
  with `eval` and no builtins, which stops a typo and does not stop anyone
  trying: `().__class__.__base__.__subclasses__()` walks from an empty tuple
  to every loaded class and from there to the ones that run commands. That
  matters here because profiles are meant to be shared — off a forum, from a
  colleague, through a pull request — so a hostile profile was a working
  supply chain attack on anyone who opened it.

  Expressions are now parsed and checked against an allowlist of syntax before
  anything runs, in `creabus_tool/expressions.py`. **Attribute access is not on
  the list**, which removes the first step of every escape of that kind;
  neither are indexing, lambdas, comprehensions, f-strings or assignment, and
  calls are only to a fixed list of maths functions. A profile that steps
  outside is refused when it loads, not caught while it runs. An absurd
  literal exponent (`10**10**8`, which is valid Python and would tie up the
  simulation thread for hours) is refused too.

  `tools/selftest.py` attempts that escape and thirteen others on every CI run.

### Added — for selling it

- **[SECURITY.md](SECURITY.md)**: where to report a vulnerability, what
  response to expect, and an honest statement of what this software does and
  does not protect — beginning with the fact that Modbus itself has no
  security whatsoever.
- **A CycloneDX software bill of materials**, generated by `tools/sbom.py` on
  the build machine so the versions in it are the versions that went into the
  binary, and shipped in every release archive.
- **[docs/eu-compliance.md](docs/eu-compliance.md)**: what has been done
  towards the Cyber Resilience Act, and — more usefully — the list of
  obligations that are organisational and cannot be met by editing code.

### Added

- **Read or write one register without polling.** Right click any row in the
  Registers table and pick *Read now* or *Write to device...*. If nothing is
  connected, the tool opens a connection for that one request and closes it
  again; if polling is already running it reuses that link, because a second
  connection to one device is wrong on TCP and impossible on an RS-485 bus.
  Checking a single value on a meter no longer means starting a full poll.
- **Five device profiles**, each stating in its own header where its register
  map came from:
  - `sunspec-inverter.yaml` — three phase PV inverter, SunSpec models 1 + 103
  - `sunspec-meter.yaml` — three phase revenue meter, SunSpec models 1 + 203
  - `plc-io.yaml` — PLC / remote I/O, exercises all four Modbus tables
  - `vfd-drive.yaml` — motor drive: control word, reference, status word
  - `climate-sensor.yaml` — small RS-485 temperature / humidity / CO2 sensor

  The SunSpec pair follow an open published specification rather than any one
  vendor's map. The other three are generic and say so: no two vendors number
  a drive the same way, so a file claiming to be one would be worse than none.
- **A palette for dark desktops**, chosen by measuring the colour the theme
  actually resolves to — which is the only thing that works on macOS, where
  the window background is the symbolic `systemWindowBackgroundColor` rather
  than a hex value.
- **New...** beside *Edit...*, to start a profile from a blank device.
- `--ui`, so the Windows command line build can still open the window.
- `--version` now prints the Python and the Tk actually in use, and says if
  the Tk is too old to draw the window.
- `HOW-TO-RUN.txt` inside every release archive, saying which of the files in
  it is the one to open on that platform.
- **This changelog**, and a help section for the profile editor, which had
  none. The help now also covers reading a register without polling, the six
  digit addresses, the profiles that ship, and two more things that go wrong:
  every value being a factor of ten out, and a negative reading coming back
  as 65-thousand-something.

### Changed

- **The default poll interval is 10 seconds, not 1.** The default points at
  somebody's real switchboard.
- **The profile dropdown re-reads the folder every time it is opened**, and
  reloads the current profile if its file changed on disk. *Rescan*, *Reload*
  and *Open devices folder* are therefore no longer buttons; all three remain
  in the Profile menu, where *Open devices folder* still answers "where do I
  copy a profile to?".
- **Help moved to the status bar**, out of the row of buttons that act on the
  profile.
- **Double clicking a register reads it** when that is all it can do. It used
  to always mean *write*, so double clicking an input register on a client
  answered "Modbus does not allow a client to write" — a refusal to do the one
  thing that register can do.
- The Windows command line build (`creabus-tool-cli.exe`) **prints its help
  when given no arguments** instead of opening the window, which made it look
  like a second, identical copy of the app.
- **The window now requires Tcl/Tk 8.6 or newer** and says so plainly if it
  has less. `--headless` still runs on anything.

### Fixed

- **Addresses above 9998 in the 4xxxx column.** The five digit form has only
  four digits for the address, so a holding register at `0xFC00` came out as
  `104513` — a number no manual prints, and one that reads like a coil. The
  six digit form now takes over at the correct boundary, and the SDM120's
  serial number reads `464513`.
- **Polled rows were unreadable on a dark desktop.** The row highlight set a
  background and left the theme's own foreground, giving white text on pale
  green.
- **The Debug log stayed white** in an otherwise dark window: it is a classic
  Tk widget, which never follows the desktop, and its background was fixed in
  the code. Its eight message colours had also been chosen for white paper.
- **A race on the Modbus link.** `ModbusMaster` had no transaction lock, so a
  single register read — which runs on its own thread — could overlap with the
  poller on the same socket. Modbus cannot tell two overlapping replies apart:
  on TCP the second reader takes the first one's reply, and on RTU the two
  requests collide on the wire. Requests are now serialised, across the retry
  loop.
- **A blank window on macOS.** Apple's `/usr/bin/python3` links against the
  system Tcl/Tk, still 8.5.9, which stopped drawing this kind of window at
  macOS 10.15: the app ran, sized its window and painted nothing into it. It
  now withdraws the window and says what to do instead, naming the interpreter
  in use — because "python3" on a Mac rarely means what its owner thinks.
- Writing a register **no longer blocks the window** for the duration of the
  timeout.
- The context menu addressed its entries by position, one number per entry,
  which is how *Read now* could ever have run the write. Entries are looked up
  by name.
- **The Debug log was never actually monospaced on Linux.** `("TkFixedFont",
  9)` looks like it asks for the fixed font and does not: Tk reads the first
  element of the tuple as a family name, finds no family by that name, and
  falls back to the proportional default without complaining - so hex frame
  dumps, where the columns are the entire point, did not line up. The tables
  in the help window were collapsing the same way.

## 0.0.2 — unreleased

Merged and tested, but never tagged, so there is no 0.0.2 download. Everything
here ships as part of 0.0.3.

### Added

- **A profile editor.** Build and change a device profile without leaving the
  app: add, duplicate, reorder and delete registers, and set every field the
  schema has. It works on a copy, so closing it leaves a running server
  untouched, and it will not write a file the loader would reject — the same
  validation runs in memory before anything reaches the disk.
- **A right click menu on each register**: read one now, write one, hold one at
  a value, release it, or copy its address, its 4xxxx address, its value or the
  whole row as a spreadsheet line.
- **4xxxx / 3xxxx addresses.** A checkbox under the Registers table switches
  the Address column between the protocol address on the wire and the number
  printed in device manuals. Mixing the two up is the usual reason a value
  comes back from the wrong place.
- **An in-app help window**, ten sections covering the tool and the parts of
  Modbus that catch people out. (0.0.3 adds an eleventh, on the editor.)

## 0.0.1 — 2026-09-09

First public release: [v0.0.1](https://github.com/CreavisionTechnology/creabus-tool/releases/tag/v0.0.1),
with standalone builds for Windows, Linux, macOS Intel and macOS Apple
silicon.

### Added

- A Modbus **server** that simulates a device, and a **client** that polls a
  real one, in one window — over Modbus TCP or Modbus RTU.
- Device behaviour comes entirely from a **profile file**. Two Eastron energy
  meters ship with it, plus a commented template.
- Four live views: Registers, Traffic, Debug log and Connections.
- A **headless mode** and a full command line, so everything the window does
  can be done on a server or in a script.
- Simulation modes — walk, random, fixed, expression and accumulator — so a
  simulated meter is internally consistent rather than merely random.

### Notes

The first archives published under this tag had their executable bit stripped
in transit, so the macOS `.app` would not open. The tag was moved to the fixed
build and the archives replaced the same day; the assets now on the release
page are the good ones. The build refuses to publish an archive whose binaries
are not executable, so this cannot recur silently.
